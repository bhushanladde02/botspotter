What is BotSpotter?

Every day, thousands of AI bots crawl the internet. Some are collecting pages to train the next big model. Some are indexing the web for AI search answers. Some are fetching a page right now because a person just asked ChatGPT or Claude a question. Most websites never see any of it.

BotSpotter makes it visible. A network of volunteer websites and honeypots reports every bot visit here. We count them live, put them on the map, and give each bot a name that stays the same wherever it shows up — so Copper Heron #0042 is the same bot on your blog, on a news site, and on a server in Singapore. When a bot nobody has seen before appears on three independent sites, it gets discovered and named here first.

Three kinds of AI bot

  • Training crawlers — bulk-read the web to train models (GPTBot, ClaudeBot, Bytespider, Common Crawl).
  • AI search — index pages so an AI can answer with citations (OAI-SearchBot, PerplexityBot).
  • AI agents — fetch a page on behalf of a live user, this second (ChatGPT-User, Claude-User).

Plus the unidentified ones: automation that hasn't announced itself. Those are the interesting ones. They get names too.

Why it matters

  • If you run a website: find out which AI companies are reading your pages and how often — free, two-minute install, no code for Nginx/Apache. Add your site as a sensor and climb the leaderboard.
  • If you're curious: watch the AI economy happen in real time. Which countries are crawled most? Whose bots are busiest? What showed up this week that didn't exist last week?
  • If you write or research: a public, live, citable source on AI crawler activity that isn't owned by a single cloud provider.

Run a bot? Claim it

Operators can claim their bot: prove control (make the bot fetch a one-time URL, or publish a token on its homepage), then give it a proper name, description and category. Claimed bots carry a ✓ and the generated name stays as an alias.

What we don't do

We don't store IP addresses, page contents, or anything about human visitors beyond a daily count. Bots are named by a hash, never exposed. Humans are counted without cookies. The numbers here are visits seen by participating sites, not “the whole internet” — the more sensors join, the closer it gets.

Same bot. Same name. Forever.

Add your site as a sensor

A sensor tells BotSpotter which bots visit your site. It never sends page content, cookies, header values, or your human visitors — browsers are filtered out on your server before anything leaves it. You get a public spot on the leaderboard and a private view of which AI companies read your pages.

1 · Get a sensor key

Keys are issued by hand while we're in beta. Fill this in and you'll get a key by email, usually the same day.

2 · Install (pick one)

Python app (FastAPI, Starlette, Flask, Django) — zero dependencies:

pip install botspotter-sensor

# FastAPI / Starlette
from botspotter_sensor import BotSpotterMiddleware
app.add_middleware(BotSpotterMiddleware, key="YOUR_KEY")

# Flask / any WSGI
from botspotter_sensor import wsgi_sensor
app.wsgi_app = wsgi_sensor(app.wsgi_app, key="YOUR_KEY")

# Django settings.py
MIDDLEWARE += ["botspotter_sensor.django.BotSpotterMiddleware"]
BOTSPOTTER_KEY = "YOUR_KEY"

Nginx / Apache / Caddy — no code, via Vector: add our log format, point Vector at the log file, set BS_KEY. Config files and a step-by-step are in sensors/ of the repo.

Anything else — POST JSON batches to /v1/ingest with header X-BS-Key:

{"events":[{"ua":"Mozilla/5.0 (compatible; GPTBot/1.2)",
            "headers":["host","user-agent","accept","accept-encoding"],
            "ip":"20.171.207.5","cf_country":"US","method":"GET","status":200,"path":"/robots.txt"}]}

3 · Watch it light up

Within a few minutes your site appears under Sensors with most catches, and every bot it sees gets its name. Behind Cloudflare? Nothing extra to do.

What leaves your server: header names, User-Agent, client IP (used once for country + network prefix, then discarded), method, status, and whether the path was robots.txt. Nothing else. Full detail in the terms.

5. Data: what the sensor sends and what we keep

Sent by the sensor, per request your server judges to be automated: the names (not values) of the request headers in order; the User-Agent string; the client IP address; the CF-IPCountry header if present; HTTP method and status code; the timestamp; and a flag for whether the path was robots.txt. Requests that look like ordinary browsers are filtered on your server and not sent. No page content, cookies, header values, query strings, form data, or other paths are sent.

Processed on arrival and then discarded: the IP address. We use it in memory to derive (a) a country and approximate region, and (b) for unidentified bots only, a coarse network prefix (/16, up to 65,536 addresses) that becomes part of the bot's fingerprint hash. The address itself is never written to disk, logs, or backups.

Stored: timestamp, your site id, the bot's fingerprint hash and derived name, a version-stripped User-Agent family, bot operator and category, country, region, a coarse geohash, and the robots.txt flag. Raw events are kept 90 days; hourly aggregates indefinitely.

Human visitors to this portal: we count unique visitors using salted hashes of IP and User-Agent that are fed only into HyperLogLog counters (a probabilistic structure that cannot be reversed or enumerated). The daily hash includes the date and powers “today” and “this week”; a second hash without the date powers “all time” so a returning person is counted once. We also count visits per country and per referring domain (e.g. linkedin.com, “direct”) — never the referring page or path. No per-visitor record is written anywhere. No cookies, no local storage identifiers, no third-party analytics scripts.

Legal basis (where GDPR/UK GDPR applies): legitimate interest in measuring automated traffic. We have designed the processing so that no personal data is retained; the IP address is processed transiently for seconds. If you believe a stored record identifies you, email us and we will remove it.
